La decisión arquitectónica sobre autenticación ha sido aprobada.

Implementa ahora únicamente la FASE 3 de MotoHub.

DECISIÓN ARQUITECTÓNICA APROBADA

ASP.NET Identity será la fuente principal de:

- autenticación
- credenciales
- roles
- claims
- confirmación de email
- recuperación de contraseña

MotoHub.Domain.User será la entidad de perfil y negocio.

MotoHub.Domain.RefreshToken será la entidad de sesiones JWT.

Los Refresh Tokens deben almacenarse únicamente como HASH,
nunca como token en texto plano.

Identity y Domain.User compartirán el mismo Guid de usuario.

MotoHub.Domain NO debe depender de ASP.NET Identity.

Infrastructure implementará los adaptadores y servicios técnicos.

Application expondrá los casos de uso y abstracciones.

API configurará:

- JWT
- autorización
- CORS
- rate limiting
- endpoints

Flutter consumirá únicamente el contrato HTTP de autenticación.

ARQUITECTURA

Mantener:

MotoHub.Domain
MotoHub.Application
MotoHub.Infrastructure
MotoHub.Api

No introducir dependencia de ASP.NET Identity dentro de Domain.

Los controllers deben permanecer delgados.

La lógica de negocio debe estar en Application/Domain.

Infrastructure debe contener las implementaciones técnicas.

SEGURIDAD

Nunca:

- almacenar passwords en texto plano
- almacenar Refresh Tokens en texto plano
- registrar passwords en logs
- registrar JWT en logs
- registrar Refresh Tokens en logs
- almacenar secrets directamente en código

Implementar correctamente:

- expiración de Access Token
- expiración de Refresh Token
- rotación
- revocación
- detección de reutilización cuando corresponda
- autorización
- validación de entrada
