5. REFRESH TOKEN
==================================================

ESTA ES UNA REVISIÓN CRÍTICA.

Verificar que exista coordinación de refresh concurrente.

Caso:

Request A → 401
Request B → 401
Request C → 401

Debe utilizarse un único refresh.

NO debe producir:

A → refresh 1
B → refresh 2
C → refresh 3

Verificar:

- Future compartido / mecanismo equivalente.
- Solo un refresh concurrente.
- Solicitudes esperando correctamente.
- Nuevos tokens guardados.
- Requests originales reintentados.
- Cada request reintentada máximo una vez.
- No existen loops infinitos.
- Refresh endpoint no entra en el mismo ciclo de refresh.
