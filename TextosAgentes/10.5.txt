3. PROBLEMAS ENCONTRADOS
3.1 ApiClient necesita refactor interno
api_client.dart funciona conceptualmente, pero tiene formato e indentación inconsistente.

También contiene un problema funcional:

bool _refreshing = false;

Si varias solicitudes reciben 401 al mismo tiempo, las solicitudes posteriores mientras _refreshing == true fallan directamente en lugar de esperar el refresh en curso.

Debe utilizarse una coordinación compartida, por ejemplo:

Future de refresh reutilizable.
Cola de solicitudes.
Mutex lógico.
Un único refresh concurrente.
3.2 Manejo de errores incompleto
app_exception.dart solo define:

NetworkException
UnknownException
No existen tipos diferenciados para:

400
401
403
404
409
422
429
500
503
timeout
respuesta inválida
error de serialización
Actualmente AuthCubit expone:
error.toString()

Eso puede mostrar mensajes técnicos de Dio al usuario.

3.3 No existe una capa central de mapeo de errores
AuthDataSource deja que los DioException suban directamente al repositorio.

La separación deseable sería:

DioException
    ↓
InfrastructureException
    ↓
Failure de dominio/aplicación
    ↓
Estado del Cubit
    ↓
Mensaje visible en español

3.4 AuthCubit está incompleto
auth_cubit.dart contiene:

restore
login
logout
No contiene:

register
forgotPassword
recuperación de contraseña
confirmación de email
cambio de contraseña
estado de sesión restaurando
estado de sesión expirada
actualización reactiva para GoRouter
El repositorio sí contiene register y forgotPassword, por lo que no se deben duplicar; el Cubit debe reutilizar esas operaciones.

3.5 El repositorio no tiene casos de uso
La interfaz de dominio apunta directamente al repositorio desde el Cubit.

Para una infraestructura pequeña esto funciona, pero para mantener Clean Architecture y SOLID sería preferible agregar casos de uso de autenticación, al menos:

RestoreSession
Login
Register
Logout
ForgotPassword
No se deben crear casos de uso para futuras funcionalidades de negocio.

3.6 Logout no es resiliente
En auth_repository_impl.dart, si la llamada remota de logout falla, el almacenamiento local no se limpia porque el clear() ocurre después del await.

Esto puede dejar tokens locales aunque el usuario haya solicitado cerrar sesión.

La política recomendada:

Intentar revocar en API.
Limpiar siempre tokens locales.
Propagar el error remoto únicamente si la interfaz necesita informarlo.

3.8 Problema potencial con GetIt en tests
main.dart obtiene AuthCubit desde GetIt.

Sin embargo, el widget test construye MotoHubApp directamente. Si no se ejecuta antes configureDependencies(), puede producir un error de registro faltante:
AuthCubit is not registered inside GetIt

La prueba debe aislar dependencias mediante:

Setup de GetIt en el test.
Registro de mocks.
Constructor configurable de la aplicación.
Provider explícito para tests.
